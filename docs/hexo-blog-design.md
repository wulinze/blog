# 个人技术博客 Hexo 整理与部署方案

## 目标与维护入口

以 `/mnt/d/note/blog`（`https://github.com/wulinze/blog.git`）作为唯一博客源码维护入口，网站继续使用 `https://wulinze.github.io/`。主要发布技术分享与技术探讨，为个人简介、项目和其他主页入口预留配置位置。

## 已核实的现状

- 源码已有 Hexo 7、71 篇 Markdown 文章和本地图片。
- 55 篇算法文章未设置日期；原发布目录可用于核对 70 篇文章的历史链接。
- 当前启用 maple，但其 Git 子模块缺少配置；另有未使用的主题子模块。
- 站点语言为英文、URL 为 example.com；尚无构建部署 workflow。
- 两篇文章引用缺失的 Windows 本地图片；其他图片需要统一为可发布路径。
- 发布仓库与在线首页当前均为空内容，不能作为正文恢复来源。

## 方案比较与推荐

1. **推荐：Hexo + NexT 阅读型主题**。通过 npm 固定依赖，保留 Markdown 写作方式，以配置实现分类、目录、搜索、代码高亮和数学公式，维护成本较低。
2. 修复原 maple 主题。外观变化小，但需要找回子模块来源并验证兼容性，不利于长期维护。
3. 自建 Hexo 主题。首页可高度定制，但后续需自行维护页面、搜索和移动端样式，当前收益有限。

## 页面与内容组织

- 顶部导航：首页、文章分类、标签、归档、关于；首页展示简短站点介绍和文章摘要。
- 简洁浅色阅读布局，清楚的标题层级，桌面目录与移动端阅读支持。
- 五类主题：JVM 与 Java、C++、算法与数据结构、系统工程、数学与计算。算法按动态规划、图与树、双指针等添加标签，避免全部只标 C++。
- 统一 front matter：title、date、updated（如有依据）、categories、tags、description；保留技术正文和代码语义。
- 优先保留历史日期和 URL；缺日期文章先从原发布路径恢复，新增或未发布文章采用 Git 历史中可核实的日期并记录依据。
- 将图片放入可发布的公共资源目录，修复相对路径。缺失图片列入迁移说明，不生成虚假图片替代内容。
- 关于页只使用已知身份与技术方向，不编造履历；GitHub 入口使用真实账号。独立个人主页和项目链接留作后续扩展。
- 本轮只整理 blog 仓库内文章，Obsidian 笔记不自动纳入发布。

## 构建与发布

本地提供安装、检查、构建、预览命令及中文 README。GitHub Actions 在 blog 仓库构建，使用专门的 SSH deploy key 将生成文件发布至 wulinze.github.io 的 master 分支。私钥存为源码仓库 secret，公钥配置在发布仓库，密钥不写入源码。此方案保持现有个人域名，避免让 blog 仓库直接发布到 /blog/。

本地已有 SSH key 已通过 ssh.github.com:443 认证为 wulinze，两个仓库的 dry-run 推送均通过。本地使用保留历史的普通 Git 推送上线；Actions 自动发布需要另行配置 BLOG_DEPLOY_KEY，不能将构建成功描述为已经自动发布。

## 验收

- 71 篇文章均生成有效页面；文章数量不减少。
- 70 条已有文章链接逐一验证，日期在重复构建时保持稳定。
- 分类、标签、归档、搜索、代码块、公式及已有图片在预览中可用。
- 缺失图片等历史问题明确记录，不出现假装迁移成功的空文章。
- 验证移动端布局与导航，检查构建产物中的内部链接和本地资源。
- 文档说明新建文章、添加图片、预览和部署步骤。
