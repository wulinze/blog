# 学习系列：从原始材料到可学习的博客

适用于用户要求把书籍、PDF 或课程整理为连续学习博客。当前 LeetCUDA 系列的分类和编号是本项目约定；其他材料先沿用用户指定的组织方式。

## 范围、来源与覆盖

- 先读取实际材料和目录，核对版本、总章数、章节起止页及附录。文件名相近不能代替版本核对；PDF 阅读器页码与印刷页码不同要注明。截图可帮助理解，但不代替阅读对应正文。
- 建立可维护的映射：原文章节/小节、页码、博客编号、标题、permalink、完成状态、图、交互、代码与练习。核对章内的重要机制和实现，不能只让目录标题数量相等就宣称全书覆盖。
- 状态区分待写、正文完成、验证完成和已上线；验证另记 CPU、GPU 编译、设备正确性、性能和浏览器检查，不能只用一个 PASS 概括。
- 用户要求整本时，逐章完成并发布是推进方式，不是缩减范围。不要写几篇或列出剩余目录后结束交付；只有真实阻塞才说明缺什么、影响哪些章节。发生上下文接续时从映射与实际文件恢复，避免重写已完成部分或遗忘后半本。
- 以自己的讲解和例子组织内容，保留来源定位，关键结论链接原始论文、官方文档或对应版本源码。源码链接尽量固定 commit；实验数字保留设备和条件，不把原书结果写成本机测量。

## 本项目的章节与导航

- `leetcuda-20261029.pdf` 采用一章一篇；部分/主题分组只作为导航。文章标题以学习问题命名，正文保留来源章号/页码，不把原文章号当成博客编号。
- 编号接续既有系列：CUDA 基础（一）、性能分析（二，对应原文第 1 章）、Roofline（三，对应第 2 章）、归约（四，对应第 3 章）；后续博客编号为原文章号加 1。该版本 40 个编号章节对应系列（一）至（四十一），独立导读与附录另列补充，不打乱编号。
- 整个 CUDA／LeetCUDA 系列，包括基础、性能分析和路线，分类为 `LLM 推理`，在 `source/llm/index.md` 按编号入口展示。保留已有稳定 permalink，即使旧路径含 `/systems/`，也不要仅为分类迁移破坏旧链接。
- 每篇明确前置知识、可检验的学习目标、上一篇/下一篇和总目录；公开导航指向已存在的页面。路线中的待写项明确标记，不能装成已上线教程。

## 讲解深度与顺序

- 以“具体问题 → 术语 → 原理与结构 → 小例子 → 实现 → 观察与练习”串起正文，可按主题调整。先定义读者需要的术语，再使用；性能主题另外读取 `performance-learning.md`，按 bound、warp 状态、指标分组。
- 每章覆盖自己的关键推导、结构依赖、实现策略和失败原因。避免所有章节都只有相同的三段概述、通用提醒和换标题的代码。小节数量由内容决定。
- 一套输入贯穿公式、图、交互和代码，保持维度、dtype、tile/slot 编号一致。对照图上一步指出对应代码及可观察的中间量，不能把完整代码放在文末就省略实现解释。
- 图前说明要观察什么，图后沿实际输入解释路径。区分结构图、流程图、时间线；只有存在对应关系时才用箭头。按依赖、分支、循环或并行关系画图，不把所有机制压成同样的直线框图。
- 延续可编辑 Excalidraw 原图与可放大 SVG。公式说明变量、维度、单位、推导、小例子及边界；复杂图与公式的细则见性能学习约定。

## 交互演示

本用户要求该系列每篇都有交互和具体代码。交互围绕本章的学习目标，而不只是添加几个按钮。

- 可改变输入或配置，观察中间数值、布局、资源或协议状态；按需提供单步、后退、重置及完成校验。配置应能展示关键机制或边界，数量按内容决定，不固定凑四组。
- 选择预计算案例也可以，但明确是已执行模型的快照；若宣称自由输入，就应按输入重新计算并校验。网页模拟、CPU 模型、GPU 执行和性能测量分别标明。
- 至少解释“改这个参数，哪个中间量为什么改变”；显示完整输入、单位和对应步骤。异步协议演示应说明等待和复用条件，顺序状态机不能声称展示了真实并发时序或硬件周期。
- 检查初始状态、改变配置、前后步、重置和最终断言；同时检查加载失败提示、手机宽度、长内容、目录遮罩、键盘可操作控件及浏览器异常。
- 展示快照时，让同一模型生成快照并核对输出；不要手写一份网页结果，再维护另一份互不相符的 demo。

## 可运行代码与两类练习

- 提供完整源码、依赖/版本、硬件条件、编译/运行命令、最小输入、预期性质和结果校验。正文解释关键代码，可折叠展示完整文件，并提供源码或实验包下载。省略号和伪代码不能标成可运行 demo。
- 教学 CPU 模型适合验证索引、数值、布局和协议。它不能替代要求交付的 GPU 实现；GPU 条件不足时仍提供明确环境条件的代码，未编译/未运行状态如实写出。
- 语义基线与本章优化实现分开。例如普通矩阵乘不能当成 TMA/WGMMA 实现，完整矩阵 Attention 不能声称为融合 FlashAttention，简化量化不能冒充完整硬件格式路径。基线解释语义，进阶实现对应本章机制。
- 若复用上游架构专用实现，提供固定版本、准确文件、依赖、目标架构和运行入口，讲清本章对应哪个函数/协议。只有仓库首页链接不算可执行的学习入口。
- Triton 和 TileLang 各自提供明确任务、输入输出契约、可修改的学生入口、提示、参考实现或参考路径、运行命令和通过条件。不要仅换文件名或列出习题名称；按两种语言真实能力设计，不强行一一对应 API。
- 未完成学生入口可以抛出 `NotImplementedError`，但应明确是练习骨架；可运行参考 demo 和验证器要另行提供。正确性参考应独立于学生/待测实现，不能调用待测代码生成期望值。
- 按算法选择非整除尺寸、尾块、对齐、mask、奇偶长度、全零/极值、数值误差或协议复用等有意义的边界。给误差口径和容差依据；不支持的输入明确拒绝。
- 正确性之后再测性能，说明 warmup、同步、重复次数、统计量、设备和版本，以及测的是单 kernel 还是包含量化、拷贝、分配的整条路径。SKIP、编译通过和 CPU 适配器通过均不能记为 GPU 正确性通过。

## 验收与发布

按本次实际改动检查，不为修正文案重复跑全套实验；批量新建系列需要覆盖新增页面和资产。

- 内容：章节/重要小节覆盖，编号、分类、来源页码和稳定地址准确；无待填写占位冒充正文；学习目标能由例子与练习验证。
- 模型与代码：完整文件能独立运行，网页中间结果与模型一致，边界有校验；分别报告静态检查、CPU 执行、GPU 编译、设备正确性、性能测量。
- 页面与资产：实际渲染的加粗、公式、表格、图、代码和交互正常；SVG 标签不截断，原图可编辑，下载包包含命令所需的文件且与源码版本一致；桌面和手机均可操作。
- 发布：完成仓库要求的构建/链接检查，选择性提交相关文件；核对源码推送、网站部署和线上页面，不能把构建通过等同上线。抽查或全量验证范围如实记录。
- 最终交付：给总目录和接续入口，说明新增篇数/覆盖范围、实际上线状态与尚未验证的设备条件。完整覆盖与 GPU 验证是两项独立结论。

- `docs/learning/validation-20261102.md`：历史验证证据；后续按实际变化补充记录，不复制旧 PASS 当成本次结果。
